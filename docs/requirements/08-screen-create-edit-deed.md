# 08. Экран: создание и редактирование дела

## Назначение

Экран, на котором пользователь создаёт новое дело или редактирует существующее: задаёт эмодзи/символы, название, описание и настраивает блоки вопрос-ответ (тип, порядок, обязательность).

## Элементы экрана

Экран разделён на вкладки **«Дело»**, **«Превью»**, **«Быстрый доступ»** и **«Аналитика»**.

### Вкладка «Быстрый доступ»

Какие действия записи дополнительно показываются кнопками в шапке экрана записи. В меню «⋯» остаются все действия. Сохраняется в `deeds.record_header_pinned` (порядок массива — порядок кнопок).

- Список: **Редактировать**, **Новая запись**, **Дублировать**, **Удалить**, **Справка**. Каждый пункт — карточка-чекбокс (Checkbox Cards). Когда уже выбраны два, остальные карточки недоступны.
- Включить можно не больше двух. Включённые стоят сверху; стрелки вверх/вниз меняют их порядок. Выключенные ниже, в фиксированном порядке списка.
- У нового дела включено только **Редактировать**. Пустой набор допустим: в шапке остаётся меню «⋯».
- «Перейти к делу» и «Актуализировать» здесь не настраиваются.
- С экрана записи пункт «Настроить действия» открывает эту вкладку. И сохранение, и крестик возвращают на ту же запись (если запись была открыта из истории — с тем же признаком `from: history`).

### Вкладка «Аналитика»

- **Активность** (виджеты «Сегодня», «За месяц», «Всего») — общий переключатель группы. Источник свой, отдельно от тепловой карты: по умолчанию количество записей за период; блок `number` / `scale` / `duration` — только если его выбрали в селекте «Что считать». `null` и неизвестный id — количество записей, без подстановки первого блока. Три переключателя видимости карточек «Сегодня», «За месяц», «Всего». Если пользователь выключает все три, главный переключатель группы автоматически переходит в «выкл»; при повторном включении группы, если все три были выключены, снова включаются все три карточки (дефолтный набор).
- **Стрики и записи** — общий переключатель группы; стрики (и при включённых стриках — счётчик «максимум стрика»), блок «всего записей», вложенно при включённом «всего» — счётчик «будни · выходные». Переключатель будни/выходные скрыт без «Всего», но его значение в состоянии не сбрасывается при временном выключении «Всего» (как «максимум стрика» при выключенном стрике). Если выключены и стрик, и «Всего», главный переключатель группы автоматически выключается; при повторном включении группы при полностью выключенных подпунктах восстанавливаются дефолты (стрик, максимум, «всего», будни/выходные).
- **Тепловая карта** — общий переключатель блока; при включении: свой селект «Что считать», отдельно от виджетов. По умолчанию — число записей в день; сумма по блоку `number` / `scale` / `duration` — только при явном выборе. Цвет карточки и градиента карты — `card_color` (селект пресетов Radix шаг 9 + пикер; пусто — акцент темы). Дополнительно: подписи дней недели слева, подписи месяцев над сеткой, нижний ряд «пик» и легенда «Меньше» … «Больше».

Конфигурация аналитики сохраняется в `deeds.analytics_config` (JSON, версия 1); цвет карточки дела — в `deeds.card_color`.

### Вкладка «Превью»

- Карточка-чекбокс на каждый блок (Checkbox Cards). Подпись — название блока или «Блок», если название пустое; длинное название переносится целиком, без «…». Порядок как у формы.
- Сохраняется в `blocks.show_in_preview`. По умолчанию все включены; новый блок тоже включён.
- Выключенные блоки не попадают в строку превью на странице дела и во вкладке «История». Если выключены все — в строке «—».
- Для «Да/Нет» «N из M» считается только по блокам, включённым в превью. Если в превью остались одни «Да/Нет», формат тоже «N из M».
- Над списком блоков — карточка-чекбокс **Счётчик (1/5)** (`deeds.fill_counter_enabled`, по умолчанию включён). Выключен — на карточке записи нет подписи «заполнено/всего». Пока включён, под ним виден чекбокс с иконкой угла **Показывать, если заполнены все поля (5/5)** (`deeds.fill_counter_show_complete`, по умолчанию выключен): тогда на карточке есть и `5/5`. Если «Счётчик» выключить, второй пункт скрывается, но его значение не сбрасывается.

### Поля дела

- **Эмодзи/символы** — выбор через emoji-mart picker (кнопка с текущим эмодзи, по клику — Popover с пикером).
- **Название** — текстовое поле.
- **Описание** — многострочное поле (textarea), необязательное. Высота поля подстраивается под объём текста (без лишней пустой высоты), но не больше 500px; при большем тексте прокрутка только внутри поля. Переносы строк сохраняются при вводе.
- **Категория** — необязательный выбор из списка или своё значение.

### Блоки вопрос-ответ

- Список блоков в текущем порядке.
- Для каждого блока:
  - Текст вопроса (заголовок блока).
  - Тип блока: Число, Текст (абзац), Один из списка, Несколько из списка, Шкала, Да/Нет, Время, Ссылка URL, Картинка. При **редактировании** сохранённого дела смена типа у блока с **уже сохранённым id** открывает **модальное окно** превью ответов по всем записям дела («Было → Стало») и подтверждения; подробности — [13-rules-editing-deed-data](13-rules-editing-deed-data.md).
  - Настройки типа (для списков — варианты и их порядок; для шкалы — число делений, подписи первого и последнего значения). Для типа **«Число»** — выпадающий список **«Единица»** с иконками: «Нет единицы», пресеты, группа **«Валюта»** (в скобках код, например `RUB`) и группа **«Другое»** со **«Свой вариант»**. Свой вариант показывает под списком полное название и сокращение в одну строку. Каталог — в [03-entity-blocks](03-entity-blocks.md). Выбор хранится в `blocks.config.unit`.
  - Секция **«Дополнительно»** (футер карточки блока): переключатель **«Обязательное поле»**; для типов «Число» и «Один из списка» — **«Подсказки из недавних записей»**; переключатель **«Подставлять при новой записи»** (флаг в БД) и редактор сохранённого значения по типу блока (значение можно хранить при выключенной подстановке). Для типа **«Число»** при включённой подстановке поле дефолта можно полностью очистить во время редактирования; при уходе с поля с пустым или невалидным значением показывается ошибка (красная обводка и текст); допустимо любое ненулевое конечное число, в т.ч. дробное; **0** не считается валидным дефолтом. Для типа **«Текст»** при обязательном блоке и пустом/пробельном дефолте ошибка также показывается при уходе с поля (как при сохранении).
  - Управление порядком: перемещение блока вверх/вниз или drag-and-drop.
  - **Удаление блока** — кнопка для удаления блока. Доступно при создании и при редактировании дела.
- Кнопка/действие **«+ Добавить блок вопрос-ответ»** — добавление нового блока (тип выбирается пользователем, по умолчанию можно подставлять «Число» для первого блока при создании дела).

### Быстрое добавление записей

- Карточка **«Быстрое добавление»** на вкладке «Дело»: переключатель сохраняется в `deeds.quick_add_defaults_enabled`.
- Пока **не у всех** блоков включена подстановка **и** сохранено валидное значение по умолчанию для типа блока, переключатель **недоступен** (пояснение в интерфейсе).
- Рядом — кнопка **«?»** с онбордингом (`help_quick_add_defaults`): короткое и длинное нажатие «+» на списке и экране дела, порядок включения.
- Если состав дефолтов перестаёт быть полным (новый блок, снята подстановка, невалидный JSON и т.д.), состояние переключателя в UI сбрасывается; при сохранении в БД уходит `false`, если условия не выполняются.
- Если **у всех блоков** уже заданы валидные значения по умолчанию, а переключатель **«Быстрое добавление»** при этом **выключен**, при нажатии «Сохранить» (после прохождения валидации формы) показывается диалог: предложить **включить** быстрое добавление и сохранить, **сохранить без** этой опции или **отменить** сохранение и остаться в форме.

### Сохранение

- Кнопка «Сохранить» (или «Создать») — сохранение дела и возврат к списку дел или к карточке дела (см. выше про диалог при полных дефолтах и выключенном переключателе быстрого добавления).

#### Условия, при которых сохранение доступно

- **Название дела** — непустое (после обрезки пробелов).
- **Хотя бы один блок** в списке.
- **Блоки «Один из списка» и «Несколько из списка»** — у каждого варианта должен быть введён собственный текст подписи (не только подсказка «Вариант 1», «Вариант 2» в поле ввода); вариантов должно быть не меньше одного.
- Если включена **подстановка при новой записи**, сохранённое значение должно быть валидным для типа блока (например, число — любое ненулевое конечное, в т.ч. дробное; выбранные id из актуального списка вариантов).
- Для типа **«Текст»**: пустое значение по умолчанию (после обрезки пробелов) допустимо **только если блок не обязательный**; для **обязательного** текстового блока при включённой подстановке нужен **непустой** текст. Иначе сохранение дела блокируется с пояснением в интерфейсе редактора дефолта.

Для **остальных типов блоков** (число, текст, шкала, да/нет, время) отдельных обязательных полей в конфиге на экране нет: пустой текст вопроса при сохранении подставляется как заголовок «Блок»; настройки шкалы и прочие поля — по умолчанию или пустые, если так в форме.

## Режимы

- **Создание**: все поля пустые, по умолчанию добавлен блок типа «Число».
- **Редактирование**: поля заполнены данными существующего дела, блоки отображаются в сохранённом порядке.

## Touch-зоны (mobile-first)

Интерактивные элементы должны иметь touch-зону не менее 44–48px по высоте/ширине для удобного нажатия на мобильных устройствах.
